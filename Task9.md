# 1 схемы создания объектов

При запуске приложения настраивается DI-контейнер: регистрируются реализации компонентов и время их жизни. Консольный ввод и вывод существуют на протяжении работы приложения.
Для каждой партии создаётся отдельная область зависимостей, содержащая игровую сессию, поле, источник элементов и очередь событий с обработчиками. Компоненты получают зависимости через конструкторы.
Перед обработкой команд выполняются подключение обработчиков и инициализация поля 8×8 элементами пяти типов. При перезапуске область предыдущей партии освобождается и создаётся новая.

# 2 обработки событий
Разделим события на команды и сами события.
- Команда — просьба выполнить действие: SwapCells, RestartGame, ExitGame.
- Событие — уже произошедший факт: CellsSwapped, ElementsRemoved, BoardSettled, GameFinished

для обработки событий возьмем queue из за FIFO соглашения.


# 3 Тесты и типовые сценарии
Координаты вне поля - команда отклонена или же игнор.
Обмен без комбинации - Согласно предложенному правилу обмен отменён, ход не засчитан.
Горизонтальная или вертикальная тройка - Удалены нужные элементы, начислены предусмотренные очки.
Пересечение комбинаций - Общая клетка удалена и учтена один раз.
Падение элементов - Порядок оставшихся элементов в столбце сохранён, пустоты заполнены сверху.
Активация бонуса - Изменены именно предусмотренные клетки, затем обработаны возникшие комбинации.
Нет доступных ходов - гг, титры и статистика
Перезапуск- полный ребут и пересоздания поля.
